# 0.0.27 review: fixes, test results, and open decisions

Branch `ssttevee/fix-0-0-27-review-items`, 87 commits on top of `18b8b01` (0.0.26). ## Items invalidated or not done, and why

- **Client compiles race the host's persistent cache** (thread 1, tier 3): invalid. The nested compile re-processes the cache config, so client compiles write to a different directory than the host; warm builds were verified correct.
- **`ctx` is stripped from custom components even when not needed** (thread 1, tier 2): invalid as written. It was only stripped from components that had an action; that narrower case was fixed (cf6fe45, 6dc3949).
- **TypeScript finds no types for the main import** (thread 1, tier 6): overstated. TypeScript fell back to `index.d.ts`, but that typed the string export as a function and the options were `any` under node16. Fixed as part of 287e8de.
- **Hyphenated param names need a build error** (thread 1, tier 2): Hono accepts any name, so the regex was widened instead (71634e4).
- **Action signing scoped by route, expiry, and actions reachable through imports** (thread 2 item 5, thread 1 tier 3): valid but deferred. Both threads recommended handling this in the TypeScript rewrite; it changes the URL format and the signature for every user. A signed scope is still accepted on another page of the same route.
- **Route scan caches never cleared in watch mode** (thread 2 item 7): valid, deferred as the threads recommended. In watch mode the app module is never regenerated, so route edits and the banned-import checks don't take effect until a restart. Same as 0.0.26.
- **The "outermost function's first param is props" heuristic** (thread 1, tier 2): a design change; not touched.
- **Inlined secret, missing Origin check, scope expiry, global mutex, persistent cache speedup**: tracked in the rewrite plan, not bugs of this release.

## Known issues found during this work (not fixed)

1. **Host `config.script` is misread through the plugin ABI.** Reading `context.config.script.parser` yields a `TsSyntax` with `dts: true` on every build with @farmfe/core 1.7.11, although nothing sets it. The plugin no longer reads it (4d4e326), but the trace and client compiles still clone the whole host config for Farm's own plugins. With default parser options this is harmless; with `script.parser.tsConfig.decorators: true` and a decorator in a route file, about 75% of builds fail with "Expression expected" (0.0.26 failed every time). Writing `config.script` from the plugin segfaults the host, so the fix is matching the host's farmfe_core layout. See the `host-script-config-mismatch` memory note.
2. **Routes outside `src_dir` render inline actions as source** (now warned about, 87aca7b). Options: transform `routes_dir` as well, or make it an error.
3. **`ctx` still renders through wrappers the plugin does not transform** (components in `node_modules` or outside `src_dir` that spread their props onto an html element). `omitCtx` only applies to spreads in transformed modules; 0.0.26 stripped `ctx` from every component with an action instead. Nested spreads like `{...{...props, title}}` are not wrapped either, and `omitCtx` also drops a user's own `ctx` key from a spread.
4. **Middleware order:** plain-directory middleware outside groups is always registered before every group's middleware, so for `(a)/x/(c)/y` next to `x/y/middleware.ts` the "shallowest to deepest" rule does not hold across that boundary.
5. **`import.meta` in an event handler** is a syntax error in the inline classic script (also 0.0.26).
6. **Actions inside event handlers** are shipped untransformed to the client (also 0.0.26).
7. **A computed `{["hx-post"]: fn}` key** isn't transformed and renders the function source (also 0.0.26).
8. **Per-handler banned-import errors stop at the first failing client compile**; only the compiled-script check reports all routes at once.
9. **Release workflow goes red on merges without a version bump** because `prepublish` fails on existing platform packages (also 0.0.26). Branch rules that required the "Test Plugin" check on pushes to main need updating now that main's checks run under the release workflow.
10. Remaining `println!` diagnostics that only reach stdout: wrong-case exports (`OnPost`), the star-export notice, and "could not find page root module" on every build without `root.tsx`.
11. Consider `"packageManager": "pnpm@9.4.0"` in package.json so local pnpm 12 stops rewriting the lockfile.

## Release-note draft

Breaking or behaviour-changing:
- Routes are registered on one app in specificity order across groups: static before `:param` before catch-all, the earlier segment deciding. A group's catch-all no longer shadows other routes; `foo/(g)/index.tsx` now matches `/foo`.
- **Group middleware semantics changed; check any middleware you rely on as a guard.** Middleware placed directly in a group directory, and middleware of plain directories inside a group, now runs as the first handlers of the group's own routes: it runs for every request one of those routes handles (including requests another route passed along with `next()`, whatever route matched first, and under any mount prefix) and once per dispatch. It no longer runs for routes of other groups or ungrouped routes under the same prefix: `(admin)/admin/middleware.ts` used to guard `(public)/admin/help`, an ungrouped `admin/*` route or an ungrouped catch-all, and now does not; move such guards to a plain `admin/middleware.ts` outside the group, which keeps prefix semantics. Middleware of plain directories inside a group still runs for requests under its directory that no route handles. Middleware runs from the shallowest directory to the deepest, counting group directories, except that plain-directory middleware outside groups is registered before every group's middleware.
- An `?action=` that names no form action of the app returns 404. The `action` query parameter is therefore reserved on every route that has form actions for the request's method: once a layout or the root component has an `hx-get` action, `GET /list?action=edit` on any page under it returns 404 where it used to render, and the same holds for `hx-post` actions and pages whose `onPost` reads `?action=`.
- Arrow `hx-on` handlers that use `this` or `arguments` fail the build.
- Two layout or route files for one directory, two directories mapping to one path, and middleware without a default export are build errors. Routes that match the same requests, i.e. the same path in several groups (`(a)/about` and `(b)/about`, which 0.0.26 registered both of, with the first by directory winning) or routes differing only in param names (`[id]` next to `[slug]`), are a build error when both respond to the same request method with a page (GET), an `on*` handler or `onRequest`; form actions of the page, its layouts and the root component don't count, since their registrations pass requests without a matching `action` along, and among such routes the page is registered first so its actions keep working. This matches decision D7 of the rewrite plan.
- Hidden directories such as `.well-known` are routed.
- `client_banned_imports` patterns also match package paths and ignore `?query`; dynamic imports and `require` in handlers are checked. Builds that passed before may fail.
- `data-hx-*` attributes are transformed like `hx-*`.
- A component that spreads its props onto an html element has `ctx` dropped from the spread; `ctx` is otherwise kept on components.
- Client scripts are always self-contained browser scripts: host target, format, externals, lazy compilation and partial bundling no longer apply to them; they are tree-shaken in dev.
- Every page gets a client script when the root component has `hx-on` handlers.
- Action URLs URL-encode route params.
- `buildHeadFn` also accepts head objects and nullish entries; `export declare` heads are no longer detected.
- Package types: the require/default entry is typed as a string; `scripts/func.d.ts` types the import entry.

Fixes: action results of any JSX-renderable type, thrown responses, duplicate charset, head mutation across requests, all head export forms, group names with dots, factory name collisions, `[module, null]` typing, nested explicit `ctx`, `ctx` on components, rest and `this` params, `[user-id]` params, empty routes dir, `routes_dir` outside `src_dir`, head-only layouts, custom `entryFilename`, root handlers, real error messages with import chains, musl packages, `isMusl`.

New: warnings for `onLoad` in layouts/root and for `routes_dir` outside `src_dir`; CI runs tests and a playground; publishing is gated on CI.
